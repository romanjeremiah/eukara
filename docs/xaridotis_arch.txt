📐 Xaridotis Core System Architecture
This document serves as the master architectural specification and developer guide for Xaridotis. The architecture balances real-time performance with asynchronous background processes, structured around a core design principle: Default to capable, fail open to capable, and eliminate runtime middleware bloat.
 









📥 Domain 1: Synchronous Ingress & Routing (Real-Time Input)
Layer A0: Ingress Context Injection (Deterministic Metadata Pre-Filter)
	•	The Problem: The routing layer cannot make intelligent contextual decisions if it evaluates messages in isolation. A message like "I'm done with this" can mean casual boredom or a mental health crisis depending on recent interactions.
	•	The Layer Structure: A programmatic database trigger automatically intercepts the incoming text stream and appends active session telemetry (current Style Card, last 3 Factual Triples, and active Mood Score) directly into the prompt metadata header.
	•	Model Choice: Handled natively via database lookup queries and code to avoid unnecessary latency.
Layer A1: The Curator (Routing & Triage)
	•	The Problem: Directing heavy structural workloads to expensive models or routing simple questions to long-latency chains degrades the user experience and spikes API costs.
	•	The Layer Structure: Evaluates input context via structural prompt constraints and outputs a unified JSON schema defining user intent (casual, emotional_vent, crisis, code, functional, multimodal_image_request).
	•	Model Choice & Tiers:
	•	Tier 1 (Primary): gemini-3.1-flash-lite (Configured with minimal output constraints for rapid, high-throughput string parsing)
	•	Tier 2 (Fallback / Fail-Open): gemini-3.5-flash (thinking_level: MINIMAL)
	•	Critical Fail-Open Mechanism: If Layer A1 hits a timeout threshold (>600\text{ ms}), the system completely bypasses triage and defaults directly to Gemini 3.5 Flash, passing the full context payload to ensure a high-fidelity response floor.
Voice Modality Intake (Speech-To-Text / STT)
	•	The Problem: Extracting audio data using heavy text models or separate external tools introduces integration bottlenecks and latency lag into conversational speech loops.
	•	The Layer Structure: Ingests raw audio waveforms natively from the user stream to transcribe text while retaining emotional cues.
	•	Model Choice & Tiers:
	•	Tier 1 (Primary): gemini-3.1-flash-lite (Native audio modality processing enables efficient transcription)
	•	Tier 2 (Fallback): gemini-3.5-flash (no thinking_level defined - leave it to the default)
📤 Domain 2: Synchronous Egress (The Response Engines)
Layer B1 & D: Standard Chat & Functional Execution
	•	Conditions: Curator flags intent: "casual" or intent: "functional". Handles everyday interaction, quick questions, system state changes (e.g., setting timers or pins), and markdown lists.
	•	Model Choice & Tiers:
	•	Tier 1 (Primary): gemini-3.5-flash (thinking_level: MEDIUM) (Maintains sub-second speeds while ensuring clean output layout without leaking formatting braces)
	•	Tier 2 (Fallback): Dual-region redundant gemini-3.5-flash instance routing.
Layer B2: The "Soul" (Deep Emotional & Crisis)
	•	Conditions: Curator flags intent: "emotional_vent" or intent: "crisis". Focuses on therapeutic conversations, processing emotional distress, and maintaining long-term attachment tracking (AEDP framework).
	•	Model Choice & Tiers:
	•	Tier 1 (Primary): gemini-3.1-pro (Equipped to handle implicit emotional subtext and deep psychological nuance)
	•	Tier 2 (Fallback): gemini-3.5-flash (thinking_level: HIGH)
Layer C: The Brain (Advanced Coding & Technical Logic)
	•	Conditions: Curator flags intent: "code". Handles algorithm creation, system scripting, and structural debugging.
	•	Model Choice & Tiers:
	•	Tier 1 (Primary): gemini-3.5-flash (thinking_level: HIGH) (Optimized for structural code generation and precise tool calling)
	•	Tier 2 (Fallback): gemini-3.1-pro
Layer H: The Expression (Multimodal Output Synthesis)
	•	Text-To-Speech (TTS):
	•	Tier 1 (Primary): Gemini 3.1 Flash TTS (Native multimodal speech generation)
	•	Nano Banana Image Generation Pipeline:
	•	Trigger: Curator flags intent: "multimodal_image_request".
	•	Tier 1 (Primary - Standard Engine): gemini-3.1-flash-image-preview (Nano Banana 2) (Used for fast composition, style transfers, and text-in-image typography parsing)
	•	Tier 2 (Premium Engine / Escalation): gemini-3-pro-image-preview (Nano Banana Pro) (Escalated for premium brand assets, infographics, high-precision visual details, or 4K layouts)
🧠 Domain 3: Asynchronous Inline Workflows (Post-Message Pipeline)
Runs instantly after the chat response is delivered to the user interface, updating internal memory stores out-of-band without blocking the interface.
Layer G & F3: Single-Pass Subconscious Processing
	•	The Layer Structure: Instead of running multiple separate queries for memory and analysis, five background sub-tasks are collapsed into a single consolidated JSON structure pass.
	•	Tasks Extracted: Knowledge Graph Node updates (F3), Mood Score/Emotions tagging, Reaction interpretation (emoji feedback), and Auto-Episode tracking.
	•	Model Choice & Tiers:
	•	Tier 1 (Primary): gemini-3.5-flash (no thinking_level defined - leave it to the default) (Ensures fast and reliable extraction of structured arrays)
	•	Tier 2 (Fallback): gemini-3.1-pro
Multimodal Representation (Vector Space Insertion)
	•	Layer Structure: Maps text, user images, and internal audio telemetry into a unified semantic matrix for Retrieval-Augmented Generation (RAG).
	•	Model Choice: gemini-embedding-2 (Natively handles multi-modal inputs, returning a dense 3072-dimensional float vector)
💤 Domain 4: Asynchronous Batch Workflows (Deep Background / Cron)
Heavier background cron jobs executed during off-peak hours to manage long-term profile data and memory synchronization.
Layer F4: Therapeutic REM Cycle
	•	The Structure: Reviews day-long conversational blocks to trace emotional trends, identify core defense mechanisms, and adjust long-term profile strategies.
	•	Model Choice & Tiers:
	•	Tier 1 (Primary): gemini-3.1-pro (Utilizes Context Caching to analyze extended chat transcripts efficiently)
	•	Tier 2 (Fallback): gemini-3.5-flash (thinking_level: HIGH)
Layer F5: The Memory Conflict Resolver
	•	The Problem: When users share updated life details, databases risk preserving contradictory information (e.g., Employed at Company A vs Just laid off from Company A), causing reasoning conflicts.
	•	The Structure: Scans the Knowledge Graph and vector database to resolve data contradictions, clean up duplicates, and deprecate old records.
	•	Model Choice & Tiers:
	•	Tier 1 (Primary): gemini-3.5-flash (thinking_level: HIGH)
	•	Tier 2 (Fallback): gemini-3.1-pro

Choosing the right Flash model
Gemini 3.5 Flash is our most intelligent and capable Flash model. However, different use cases may have different cost and latency requirements.
	•	Gemini 3.1 Flash-Lite: For low cost, high-volume tasks that don't require the advanced reasoning depth of 3.5 Flash, we recommend using Gemini 3.1 Flash-Lite. It is a stable, long-term model optimized for efficiency. See the Flash-Lite developer guide for more details.
	•	Gemini 3 Flash Preview: While we recommend migrating to 3.5 Flash for GA stability and improved reasoning, Gemini 3 Flash (Preview) remains available for developers who want to continue testing with the preview model.
Behavioral changes
New default effort level: medium
The default thinking effort is now medium, changed from high in Gemini 3 Flash Preview. medium yields very good results across a wide range of tasks while being faster and more cost-efficient. For complex problems, high encourages the model to think more deeply.
Effort level
When to use
minimal
Optimized for response speed. Chat-like use cases, quick factual answers, simpler tool calls.
low
Code and agentic tasks that require lower latency and fewer steps. Also works well for analysis and writing tasks that require some thinking.
medium (default)
Best quality for most tasks. Recommended for complex code and agentic use cases.
high
Maximizes the model's ability to think and use tools. Best for complex reasoning, hard math, and the most difficult code or agent tasks. Allows extended thoughts and function calls.

Thought preservation
The model maintains intermediate reasoning across multi-turn conversations automatically. When present in the conversation history, reasoning context carries forward, which improves performance on complex multi-step tasks like iterative debugging and code refactoring. No API changes needed:
	•	Interactions API: Thoughts are already preserved automatically. No change in behavior.
	•	GenerateContent API: Beginning with Gemini 3.5 Flash, the model uses reasoning context from all previous turns when thought signatures are present in the conversation history. To enable this, pass the full, unmodified conversation history (including thought signatures) in contents. The SDKs handle this automatically.
Note: When using the GenerateContent API, preserved thoughts increase input token count over multiple turns. For simple queries, you can clear them to reduce cost. See the thought signatures guide for details.
Parameter updates and best practices in Gemini 3.x
The following apply to all Gemini 3.x models, including Gemini 3.5 Flash.
	•	temperature, top_p, top_k: we strongly recommend not changing the default values. Gemini 3's reasoning capabilities are optimized for the default settings.
	•	Use thinking_level instead of thinking_budget.
	•	Function calling response matching: id, name, and response count must match the preceding calls.
	•	Multimodal function responses: include multimodal content inside the function response, not outside it.
	•	Inline instructions in function responses: append to the function response text, not as separate parts.
	•	Reduce unnecessary tool calls: Use lower thinking levels or experiment with system instructions to reduce tool calls in agentic workflows.
See the sections below for how to update your code.
Sampling parameters (no longer recommended)
temperature, top_p, and top_k are no longer recommended for all Gemini 3.x models. Gemini 3's reasoning capabilities are optimized for the default settings. Remove these parameters from all requests.
# ⚠️ Remove these parameters (not recommended)
config = types.GenerateContentConfig(
    temperature=0.7,
    top_p=0.9,
    top_k=40
)

To ensure determinism, we recommend defining a system instruction with explicit rules for your specific use case.
thinking_budget (no longer recommended)
The raw numeric thinking_budget parameter is no longer recommended across all Gemini 3.x models. Use the thinking_level string enum instead.
# ⚠️ Before (not recommended)
config = types.GenerateContentConfig(
    thinking_config=types.ThinkingConfig(thinking_budget=7500)
)

# ✅ After
config = types.GenerateContentConfig(
    thinking_config=types.ThinkingConfig(thinking_level="medium")
)

Available values: minimal, low, medium (default), and high.
Function calling: strict response matching
The Interactions API already errors on mismatched function responses. The GenerateContent API does not yet error, but mismatched responses cause the model to return empty responses with finish_reason: STOP in most cases. Always follow these conventions:
Requirement
Details
Include id
Every FunctionResponse must include the id from the corresponding FunctionCall
Match name
The name in the response must match the name in the call
Match counts
Return exactly one FunctionResponse for each FunctionCall received

Multimodal function responses
We often see clients provide images outside function response. This can lead to unexpected model behavior (e.g. thought leakage) and result in lower quality outputs. Follow the recommendation in Multimodal Function Responses API docs instead and include multimodal content in the function response parts that you send to the model. The model can process this multimodal content in its next turn to produce a more informed response.
Python
JavaScript
// ✅ Include multimodal content in the function response
const finalResponse = await ai.models.generateContent({
  model: "gemini-3.5-flash",
  contents: [
    ...previousContents,
    { role: "model", parts: [{ functionCall: toolCall }] },
    {
      role: "user",
      parts: [{
        functionResponse: {
          name: toolCall.name,
          id: toolCall.id,
          response: {
            result: "instrument.jpg",
            image: base64ImageData,
          },
        },
      }],
    },
  ],
  config: config,
});

Inline instructions in function responses
We often see clients provide additional instructions along with function responses as subsequent Parts. This can lead to unexpected model behavior (e.g. thought leakage) and result in lower quality outputs. Instead, append any extra instructions to the end of the function response text separated by two newlines.

  ],

Reducing unnecessary tool calls
If you experience an overuse of tool calls, two techniques help minimize them:
	•	Start by reducing the thinking level (medium, low, or minimal): Higher thinking levels encourage the model to use more tools to explore and verify, so lowering the level can reduce tool calls.
	•	Add a system instruction: If overuse persists after adjusting the thinking level, consider a prompt that restricts tool usage. For example:
You have a limited action budget of <n> tool calls. Use them efficiently.

Migrate from Gemini 2.5
All of the above, plus:
	•	Simplify prompts. If you used chain-of-thought prompt engineering to force reasoning, try thinking_level: "medium" or "high" with simpler prompts instead.
	•	Test PDF and media workloads. If you relied on specific behavior for dense document parsing, test the media_resolution_high setting to ensure continued accuracy. 	•	Leverage combined tool use. Google Search, URL context, code execution, and custom functions can be used in the same request.

	•	Remove candidate_count from your config (not supported in Gemini 3.x)
Gemini 3 family features
Gemini 3.5 Flash inherits all Gemini 3 family capabilities except Computer Use. Features introduced in Gemini 3 that carry forward:
	•	Thinking: Encrypted reasoning context preserved across API calls. Automatic in the Interactions API; implicit in GenerateContent.
	•	Structured outputs with tools: Combine JSON mode with built-in tools (Search, URL context, code execution, function calling).
	•	Multimodal function responses: Return images, audio, and other media in function call results.
	•	Code execution with images: Execute code that processes and generates images.
	•	Combined tool use: Use built-in tools and custom function calling in the same request.
	•	Media resolution: Fine-grained control over token allocation for image, video, and PDF inputs. Gemini 3 models support per-content-item resolution settings (low, medium, high, ultra_high) for mixed-fidelity prompts.
	•	Thought signatures: Encrypted representations of the model's internal reasoning. Required for multi-turn function calling; managed automatically by the official SDKs.
Prompting best practices
Gemini 3.x models are reasoning models, which change how you should prompt.
	•	Precise instructions: Be concise. Gemini 3.x responds best to direct, clear instructions. Verbose or complex prompt engineering techniques designed for older models may cause the model to over-analyse.
	•	Output verbosity: By default, Gemini 3.x is less verbose and prefers direct, efficient answers. If your use case requires a conversational tone, steer the model explicitly in your prompt (for example, "Explain this as a friendly, talkative assistant").
	•	Context management: When working with large datasets (such as entire books, codebases, or long videos), place your specific instructions or questions at the end of the prompt, after the data context. Anchor the model's reasoning by starting your question with a phrase like, "Based on the preceding information...".
Learn more about prompt design strategies in the prompt engineering guide.
